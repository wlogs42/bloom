# bloom — Expo + NativeWind

Головний екран планування дня на React Native, Expo SDK 56 і NativeWind 4.

Таймер на 15/25/45 хвилин підтримує паузу та повернення з фону. Завдання можна
додавати, фільтрувати й відмічати виконаними; вкладка «Мій ритм» показує прогрес.
Новий профіль починає з порожнього списку. Завдання, завершені сесії та стан таймера
зберігаються на сервері в SQLite й відновлюються після перезапуску.

## Вхід і реєстрація

Застосунок відкриває екран входу. Вкладка «Реєстрація» містить фото профілю, ім’я, email,
пароль (від 8 символів) і підтвердження пароля. Фото обирається з галереї
(`expo-image-picker`) і є обов’язковим. Є перевірка полів, показ/приховування
паролів, перехід на головну та кнопка виходу на мобільному й десктопному екранах.
Стилі написані через Tailwind CSS / NativeWind (`className`).

Вхід надсилає JSON, реєстрація — `multipart/form-data` з фото на ASP.NET Core API.
На головну можна перейти тільки після успішної відповіді сервера. Є обробка помилок
400/401/409, недоступного сервера, тайм-аут 10 секунд і блокування повторного надсилання.

## Запуск API та застосунку

Потрібні Node.js, npm і .NET SDK 9. SQLite-провайдер автоматично встановлюється під час
першої збірки. Окремий сервер бази даних не потрібен.

Усі команди npm запускаються з папки `mobile/`.

Термінал 1:

```sh
cd mobile
npm run api
```

API запускається на `http://localhost:5050` у режимі Development.
Тестовий користувач створюється тільки в цьому режимі:

- Email: `admin@gmail.com`
- Пароль: `123456`

Термінал 2:

```sh
cd mobile
npm install
npm start -- --clear
```

Натисніть `i` для iOS Simulator, `a` для Android Emulator або `w` для браузера.
Вебверсію також можна запустити командою `npm run web` (порт 8081).

### Адреса API на різних пристроях

| Середовище                 | Адреса API                         |
| -------------------------- | ---------------------------------- |
| Браузер / iOS Simulator    | `http://localhost:5050` (типово)   |
| Android Emulator           | `http://10.0.2.2:5050` (типово)    |
| Фізичний телефон з Expo Go | `http://IP_ВАШОГО_КОМП’ЮТЕРА:5050` |

Для фізичного телефона скопіюйте `mobile/.env.example` у `mobile/.env` і вкажіть адресу комп’ютера:

```dotenv
EXPO_PUBLIC_API_URL=http://192.168.1.100:5050
```

Телефон і комп’ютер мають бути в одній Wi-Fi мережі. API слухає `0.0.0.0:5050`;
за потреби дозвольте цей порт у локальному firewall. Після зміни `.env`
перезапустіть Expo. Ця змінна публічна й не повинна містити секретів.

CORS дозволяє вебклієнт із `http://localhost:8081` і `http://127.0.0.1:8081`.
Для іншого вебпорту додайте origin у `backend/Bloom.API/appsettings.json` →
`Cors:AllowedOrigins`. Нативні HTTP-запити React Native не залежать від browser CORS.
HTTP використовується для локальних тестів в Expo Go; для розгортання потрібен HTTPS.

## API

```http
POST http://localhost:5050/api/auth/login
Content-Type: application/json

{"email":"admin@gmail.com","password":"123456"}
```

Успіх — `200 OK`:

```json
{
  "user": {
    "id": "11111111-1111-1111-1111-111111111111",
    "name": "Адміністратор",
    "email": "admin@gmail.com",
    "photo": null
  },
  "token": "<JWT>"
}
```

Неправильні дані — `401`, некоректне тіло запиту — `400`.
`GET /health` перевіряє доступність API.

### Реєстрація з фото

`POST /api/auth/register` приймає `multipart/form-data` з полями `name`, `email`,
`password` і файлом `photo` (JPEG, PNG або WebP до 5 МБ). Успіх — `201` з тим самим
тілом, що й вхід: користувач і JWT. `user.photo` — шлях до файлу, наприклад
`/uploads/<назва>.jpg`; фото віддається за `http://localhost:5050/uploads/...`.
Без фото або з файлом, який не є зображенням, — `400`; повторна пошта — `409`.

```sh
curl -i http://localhost:5050/api/auth/register \
  -F name=Богдан -F email=bohdan@example.com -F password=my-password-123 \
  -F photo=@photo.jpg
```

Готові запити для редактора є у `backend/Bloom.API/Bloom.API.http`.

### Seed-користувачі

У режимі Development під час старту API додає в базу користувачів, яких там ще немає
(`backend/Bloom.API/Seed/UserSeeder.cs`). Паролі зберігаються лише як хеш.

| Ім’я          | Пошта             | Пароль     |
| ------------- | ----------------- | ---------- |
| Адміністратор | `admin@gmail.com` | `123456`   |
| Олена         | `olena@gmail.com` | `olena123` |
| Тарас         | `taras@gmail.com` | `taras123` |

### Postman

Імпортуй `backend/Bloom.postman_collection.json` (Import → File). Запити «Login — admin»
і «Register — з фото» зберігають JWT у змінну колекції, тож «Профіль за токеном» працює
одразу після них. Для реєстрації відкрий Body → form-data і в полі `photo` обери файл.
Адресу API задає змінна `baseUrl` (типово `http://localhost:5050`).

```sh
curl -i http://localhost:5050/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@gmail.com","password":"123456"}'
```

## Вхід і реєстрація через сервер ITStep

Кнопка «Увійти через сервер ITStep» на екрані входу відкриває окрему сторінку
(`mobile/src/features/itstep/RemoteLoginScreen.tsx`) з вкладками «Вхід» і «Реєстрація». Запити йдуть на
`https://webpd411.itstep.click` (`mobile/src/features/itstep/api/`):

- вхід — `POST /api/Account/Login`, JSON `{email,password}`;
- реєстрація — `POST /api/Account/Register`, `multipart/form-data` з полями `FirstName`,
  `LastName`, `Email`, `Password`, `ConfirmPassword` і необов’язковим файлом `ImageFile`.

Успіх обох запитів — `200` з `{ "token": "<JWT>" }`.

Після успішного входу або реєстрації застосунок одразу відкриває список задач користувача.
Унизу є панель із вкладками «Задачі» та «Профіль». Сторінка профілю
(`mobile/src/features/itstep/RemoteProfileScreen.tsx`): надсилає `GET /api/Account/Profile` із заголовком
`Authorization: Bearer <JWT>` і показує фото, ім’я, прізвище, пошту та ролі. Поле `image`
у відповіді — це назва файлу без розширення; саме фото лежить за адресою
`/images/<image>_800.webp` (є також розміри `64` і `1280`). Якщо фото немає, показується
іконка. Після входу JWT зберігається (на телефоні — Expo SecureStore, у вебі — sessionStorage),
тому після перезапуску застосунок одразу відкриває профіль. Прострочений токен не
відновлюється. Кнопка «Вийти» видаляє токен і повертає на екран входу.

Застосунок показує всі помилки сервера:

| Відповідь сервера                                   | Що бачить користувач                         |
| --------------------------------------------------- | -------------------------------------------- |
| `400 {"error":"Дана пошта уже зареєстрована"}`      | цей текст під полем пошти й у повідомленні   |
| `400 {"error":"Passwords must be at least 6 ..."}`  | переклад вимоги під полем пароля             |
| `400 {"errors":{"FirstName":["... is required."]}}` | «Заповни це поле.» під кожним названим полем |
| `401`                                               | «Неправильна пошта або пароль.»              |
| `413`                                               | фото завелике для сервера                    |
| `5xx`, тайм-аут, немає мережі                       | окреме повідомлення для кожного випадку      |

### Задачі користувача

Вкладка «Задачі» (`mobile/src/features/itstep/RemoteTasksScreen.tsx`) відкривається першою після входу чи
реєстрації. Угорі — привітання з фото, картка прогресу (виконано / усього, відсоток,
прострочені) і фільтр за статусом. Кожна задача — картка з кольором пріоритету, статусом
і терміном; прострочені позначені червоним. Кругла кнопка «+» створює нову задачу. Усі запити
йдуть із `Authorization: Bearer <JWT>`, і сервер повертає лише задачі власника токена:

- список — `GET /api/Tasks`; статуси й пріоритети — `GET /api/Tasks/statuses` та
  `GET /api/Tasks/priorities`;
- створення — `POST /api/Tasks`, зміна — `PUT /api/Tasks/{id}` з JSON
  `{title, description, dueDate, statusId, priorityId}`.

Назва обов’язкова (до 200 символів), опис і термін — ні. Термін вводиться як `ДД.ММ.РРРР`.
Помилки сервера показуються під полями: порожня назва, неіснуючий статус або пріоритет;
`404` — «Задачу не знайдено!», `401` — повернення на екран входу.

Сервер не перевіряє формат пошти та збіг паролів, тому ці правила перевіряє сам застосунок
перед надсиланням. Сервер також не віддає CORS-заголовків, тож у вебверсії браузер блокує
запит — перевіряй в Expo Go, на емуляторі Android або симуляторі iOS.

## Структура бекенду

За зразок розділення шарів взято
[Digital-Bank-Monobank](https://github.com/wlogs42/Digital-Bank-Monobank/tree/main/backDigitalBank).
Реалізація адаптована для цього навчального застосунку:

- `Bloom.API` — HTTP-контролер, контракти, валідація, CORS, DI та тестовий користувач.
- `Bloom.Application` — сервіси входу/реєстрації та інтерфейси репозиторію й хешування.
- `Bloom.Domain` — модель користувача.
- `Bloom.Infrastructure` — SQLite-репозиторій, атомарні транзакції й ASP.NET PasswordHasher.

Рішення: `backend/Bloom.sln`. Клієнт запитів: `mobile/src/shared/api/client.ts`.

## Особистий простір

- **Профіль:** іконка користувача у шапці, вкладка в навігації, зміна імені, пошти й пароля.
- **Завдання:** створення, редагування, виконання, фільтри та видалення з підтвердженням.
- **Фокус:** сервер зберігає початок, паузу й залишок часу. Таймер переживає закриття
  застосунку та перезапуск API; завершена сесія зараховується лише один раз.
- **Прогрес:** справжні хвилини фокусу за поточний локальний день, тижневий графік,
  останні 20 сесій і загальні показники у профілі. Готові завдання рахуються за всі дні.
- **Синхронізація:** дані перечитуються при поверненні в застосунок, кожні 15 секунд
  та потягуванням екрана вниз. Зміни показуються після підтвердження сервера.
  Без підключення до API нові зміни не зберігаються; застосунок показує помилку.

База: `backend/Bloom.API/App_Data/bloom.db` (створюється автоматично, не потрапляє в Git).
Інший шлях можна задати змінною `Database__Path`. Зберігайте цей файл разом із даними
SQLite WAL/SHM або робіть SQLite backup перед перенесенням під час роботи сервера.

Після входу й реєстрації API видає JWT (HS256) на 30 днів із `sub` — ID користувача,
`email`, `name` та `jti` — ідентифікатором сесії. У SQLite зберігається лише хеш `jti`,
тому токен перестає діяти після виходу. Ключ підпису задається через `Jwt__Key` (base64);
якщо його немає, API генерує `App_Data/jwt.key`. Фото лежать в `App_Data/uploads`
(інший шлях — `Uploads__Path`). Обидва не потрапляють у Git.
На телефоні токен зберігається через Expo SecureStore; у вебі — sessionStorage
(переживає reload, але закривається разом із браузерною сесією). Паролі хешуються й
не повертаються клієнту. Вихід відкликає сесію на сервері, а зміна пароля завершує
інші сесії. Якщо сервер недоступний, екран відновлення входу дозволяє повторити запит.

Всі особисті маршрути потребують `Authorization: Bearer <token>`. Сервер визначає
користувача із сесії — чужий ID завдання не дає доступу до чужих даних:

| Метод        | Маршрут              | Дія                                                                               |
| ------------ | -------------------- | --------------------------------------------------------------------------------- |
| GET / PUT    | `/api/me`            | Читання / редагування профілю                                                     |
| PUT          | `/api/me/password`   | Зміна пароля: `currentPassword`, `newPassword`                                    |
| POST         | `/api/me/logout`     | Вихід                                                                             |
| GET          | `/api/me/workspace`  | Завдання, таймер та історія фокусу                                                |
| POST         | `/api/me/tasks`      | Створення завдання                                                                |
| PUT / DELETE | `/api/me/tasks/{id}` | Редагування / видалення свого завдання                                            |
| POST         | `/api/me/timer`      | `action`: `start`, `pause`, `reset`, `duration`; для duration — `durationMinutes` |

Попередній тестовий акаунт `admin@gmail.com / 123456` створюється тільки в Development,
без вигаданих завдань і статистики. Зміну його імені, пошти або пароля перезапуск не скидає.
Для власного користування можна створити новий акаунт через реєстрацію.

## Стилі

- NativeWind 4 використовує Tailwind CSS 3 та `className` у React Native компонентах.
- Палітра і шляхи до компонентів налаштовані в `mobile/tailwind.config.js`.
- `global.css` містить директиви Tailwind та імпортується з `mobile/index.ts`.
- Metro збирає CSS через `withNativeWind`; вебверсія також використовує Metro.
- Пресет `nativewind/babel` уже підключає Worklets через Reanimated. Автоматичне
  підключення цього плагіна у пресеті Expo вимкнено, щоб уникнути дублювання.

Після зміни Babel або Metro перезапустіть Expo з `--clear`.

## Перевірки

```sh
npm run typecheck
npm run lint
dotnet build ../backend/Bloom.sln
npm run test:api # API має бути запущений
```

`test:api` перевіряє вхід, розділення даних двох акаунтів, CRUD завдань, зміну профілю
і пароля, відкликання сесій, паузу/скидання таймера та справжню хвилину фокусу (~65 с).
Скрипт створює окремі тестові акаунти; для ізоляції можна запустити API з тестовим
`Database__Path` та передати `API_TEST_URL=http://127.0.0.1:5051` у скрипт.
